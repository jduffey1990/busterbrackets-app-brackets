# brackets service: agent instructions

Global rules live in `~/.claude/CLAUDE.md` and apply here.
This file adds what is specific to the BusterBrackets brackets microservice.
The build plan and per-phase "as built" records are in `docs/PLAN.md`.

## What this service is

Node + Hapi + TypeScript + MongoDB.
It owns brackets, tournament data (the field and official results per year), the derived game history, the AI breakdown, and the news feed.
The `users` service owns accounts and issues the JWT this service validates.
The `ui` repo (Vue + Vuetify) is the only client.
Each of the three is its own git repo under `~/code/buster`; `docker-compose.yml` in the parent folder runs the local stack.

## Invariants

- Every route is JWT-protected by default (`server.auth.default('jwt')`).
  Anything that writes tournament data or games calls `assertAdmin`.
  Admin is a single user id in `ADMIN_USER_ID`; there is no role model.
- Pure algorithm modules (`gameDerivation`, and the odds and simulation modules that follow) import nothing from `mongodb` or `@hapi`.
  Mongo access lives in `*Service.ts` classes in `src/controllers/`; routes stay thin.
- Seed keys are `e1`..`e16`, `m1`..`m16`, `s1`..`s16`, `w1`..`w16`.
  Round-of-64 pairing order is `ROUND_OF_64_ORDER` in `gameDerivation.ts`.
- `tournamentGames` is derived state: rewritten whole per year from `tournamentData.results`, never edited by hand.
  Nothing references it by foreign key.
- Seed and rebuild scripts are additive for `tournamentData` and `brackets`.
- `dist/` is tracked and regenerated by `npm run build`; do not edit it.

## Run and test

```bash
cd ~/code/buster && docker compose up -d            # mongo, users, brackets, ui
cd ~/code/buster/brackets
npm test                                            # jest, no database needed
npx tsc --noEmit                                    # the lint step
npm run rebuild-games                               # re-derive tournamentGames from tournamentData
npm run backfill-games                              # load src/data/historical-games.json for untracked years
```

## Branches, commits, and the gate

New work happens on a `feat/`, `fix/` or `chore/` branch, never on `main`.
Leave changes uncommitted for Jordan to review in the VS Code diff; commit only when asked, one logical change per commit.
This repo is gated by no-mistakes (`.no-mistakes.yaml`).
Jordan pushes a finished branch to the `no-mistakes` remote himself, or asks an agent to drive `no-mistakes axi run --intent "..."`.
The gate reviews, runs `tsc` and jest, forwards the branch to `origin`, and opens the PR; the config is honored only from the copy on `main`.
Production is AWS and Jordan's alone: no deploys, no production Mongo, no `terraform apply`.

## Phase gate

Run this at the end of every phase, before starting the next.
Spawn review subagents in parallel, or work through the items in sequence.
Fix what they find, and record the outcome under a **Phase gate - as built** heading in the phase's section of `docs/PLAN.md`, one line per item, so a fresh session can read what was checked and what was left.
The no-mistakes gate owns test execution and the correctness and security review and records its evidence in the PR body, so this gate keeps only what the pipeline does not do.

1. **Test coverage.** New pure modules, services and endpoints have jest tests.
   Every new admin-only endpoint has a non-admin 403 case and an unauthenticated 401 case once a route harness exists.
   Update the expected test count in `docs/PLAN.md`.
   List every gap explicitly, including anything verified only by hand against the running stack.
2. **DRY.** Remove duplication the phase introduced or touched.
   Usual suspects here: bracket-structure constants (round-of-64 order, region prefixes) re-declared instead of imported from `gameDerivation.ts`; odds or simulation math living in both `ui/` and this service; hand-built bracket fixtures in tests instead of `src/data/`.
3. **Modularity.** Routes call services; services own Mongo; pure modules own math.
   The UI reaches this service only through its `$brackets` axios plugin.
4. **Orthogonality.** A change to one concern (auth, tournament data, odds, simulation, breakdown, news) should not force edits in another.
   Where coupling is unavoidable, note it in a code comment and in the list below.
   Known unavoidable cases:
   - the seed-key format and the round-of-64 order are shared by `ui/src/utils/bracketStruc.js`, `src/models/tournamentData.ts`, the admin validation in `tournamentDataRoutes.ts`, and `gameDerivation.ts`;
   - `StructuredBracket` is the wire shape for brackets, official results, and the simulation output, so a shape change touches `ui/src/views/Admin.vue`, `Builder.vue`, `Bracket.vue` and every service here;
   - host ports and `MONGO_URI` are agreed between `../docker-compose.yml`, each service's `.env`, and `ui/src/plugins/axios.js`;
   - the `.no-mistakes.yaml` commands and `.github/workflows/ci.yml` must run the same checks; change one, change both;
   - the Node version appears in `Dockerfile`, `.github/workflows/ci.yml`, and the nvm path in `.no-mistakes.yaml`.
5. **Branch and production guard.** Confirm the phase's work is on its branch, nothing was committed to `main`, and nothing touched AWS or a production database.
